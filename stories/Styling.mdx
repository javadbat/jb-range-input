<Title>Styling</Title>

`JBRangeInput` styling is theme-driven. Use common design tokens for product-level consistency, component variables for the range input API, and CSS parts only for official exposed surfaces.

## Common Design Tokens

Use the core theme docs as the source of truth for shared design-system variables:

- [Theme Colors](../../jb-core/theme/stories/colors.mdx) explains the general color palette variables, default colors, customization approaches, and color generation helpers.
- [Theme Sizes](../../jb-core/theme/stories/sizes.mdx) explains shared size and radius variables.
- [Theme Custom Galleries](https://javadbat.github.io/design-system/?path=/docs/theme-custom-material--docs) gathers the shared custom style recipes across components.

Range input recipes should use those common tokens where possible, then map them into `--jb-range-input-*` variables only where the range input needs a component-specific value.

In single mode, `startPoint` controls where the active line begins. If it is omitted, it follows the same default as `value`: zero when zero is within the range, otherwise `min`. It is ignored in range mode.

## Styling Model

- Reusable example theme packs live in [`docs/styles`](https://github.com/javadbat/design-system/tree/main/docs/styles).
- Component recipes live in [`modules/jb-range-input/stories/styles`](https://github.com/javadbat/design-system/tree/main/modules/jb-range-input/stories/styles).
- Public component variables use the `--jb-range-input-*` prefix and are the stable styling API.
- Exposed parts provide targeted effects and styling when a variable is not sufficient.

Each style story combines one shared theme class with one range-input-specific recipe on `JBRangeInput`.

## Recommended Customization Path

1. Use `--jb-range-input-*` variables first for track, active track, ticks, handles, balloon, label, and message styling.
2. Use shared variables from [Theme Colors](../../jb-core/theme/stories/colors.mdx) and [Theme Sizes](../../jb-core/theme/stories/sizes.mdx) when the value should follow the design system.
3. Use host styles for layout context such as width and surrounding spacing.
4. Use `::part(...)` for targeted effects such as handle shadows or track filters.
5. Put reusable theme values in `docs/styles`; keep range-input-specific mappings in this component's `stories/styles` folder.

## Theme File Pattern

Use [Theme Colors](../../jb-core/theme/stories/colors.mdx) and [Theme Sizes](../../jb-core/theme/stories/sizes.mdx) as the common design-token guides. Shared theme-pack values belong in [`docs/styles`](https://github.com/javadbat/design-system/tree/main/docs/styles), while range-input-specific CSS belongs in [`modules/jb-range-input/stories/styles`](https://github.com/javadbat/design-system/tree/main/modules/jb-range-input/stories/styles).

```css
/* docs/styles/carbon.css */
.theme-name-style {
  /* shared design-system variables */
}

/* modules/jb-range-input/stories/styles/style-carbon.css */
jb-range-input.theme-name-style {
  /* range-input-specific variables and official parts */
}
```
